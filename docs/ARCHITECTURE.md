# 四旋翼巡检系统：当前详细架构

更新日期：2026-10-07。本文描述工作区当前代码，包括定位、坐标、地图、全局与局部规划、执行保护、Qt 和仿真启动。以源码实际行为为准；设计建议、尚未验证的事项单独列出。

当前处于仿真阶段，未完成实机验收。最新分离启动入口和 Qt 模式显示已编译、通过脚本语法检查，尚未完成这两个新入口的 ROS/Gazebo 联调。本文不是“所有仿真项目已通过”的验收报告。

## 1. 系统组成与数据流

系统基于 ROS Noetic、Gazebo Classic 11、PX4 SITL、MAVROS、Faster-LIO、修改后的 EGO-Planner，以及嵌入 RViz 的 Qt 操作台。

```mermaid
flowchart TD
    G[Gazebo 世界与四旋翼] --> R[原生雷达扫描和雷达 IMU]
    R --> A[C++ Livox 适配器]
    A --> L[Faster-LIO]
    L --> B[LIO 桥接与机体位姿换算]
    B --> EV[/mavros/odometry/out 外部位姿]
    EV --> F[PX4 EKF]
    G --> I[飞控 IMU]
    I --> F
    F --> O[MAVROS 本地位置与速度]
    A --> RAYS[建图命中点与未命中射线]
    RAYS --> ALIGN[扫描时刻 FCU 位姿与雷达外参]
    O --> ALIGN
    B --> ALIGN
    ALIGN --> M[共享三维占据 空闲 膨胀地图]
    FILE[预建 dmap 体素存档] --> SESSION[地图会话与初始位姿对齐]
    SESSION --> M
    M --> ASTAR[全局 A* 与曲线平滑]
    Q[Qt 当前目标与目标队列] --> FM[飞行管理器]
    FM --> ASTAR
    ASTAR --> Y[黄色全局参考路线]
    Y --> E[EGO 滚动局部规划]
    M --> E
    O --> E
    E --> GUARD[轨迹与已观测空间审核]
    M --> GUARD
    GUARD --> P[紫色批准执行轨迹]
    P --> FM
    O --> FM
    FM --> SP[持续位置 速度前馈 yaw 设定值]
    SP --> F
    G --> CAM[前视 下视相机]
    CAM --> PROC[仿真图像处理]
    PROC --> Q
    M --> Q
    Y --> Q
    P --> Q
```

上图中“扫描时刻对齐”是当前地图输入路径，不表示 FCU 与 LIO 原始数值已经完全一致。Faster-LIO 的内部匹配地图与共享规划地图是两种不同数据结构。

## 2. 仿真世界、机体与传感器

默认世界是 [inspection_demo.world](../src/drone_stack/worlds/inspection_demo.world)，包含地面、墙体、柱体、设备和相机检测目标。机体使用 `inspection_quad` 模型，由生成脚本及 PX4 仿真启动流程准备。

| 项目 | 当前配置 |
|---|---|
| 雷达安装位置 | 相对机体参考中心 `[0.27, 0, 0.10] m` |
| 雷达安装角 | ROS FLU 中绕 +Y 转 +30°，雷达 X 轴向下倾斜 |
| 雷达扫描更新率 | 10 Hz |
| 扫描范围 | 雷达自身坐标水平 360°，垂直约 −7°～+52° |
| 扫描采样 | 水平 360、垂直 56；约 20160 条射线/帧 |
| 仿真距离参数 | 0.1～40 m，距离分辨率配置 0.02 m |
| 雷达 IMU | 200 Hz，与仿真雷达坐标重合 |
| 飞控 IMU | 250 Hz；独立于雷达 IMU |
| 相机 | 前视、下视，模型中相机配置 15 Hz |
| GPS/气压计/磁力计 | 模型移除相应来源，PX4 参数关闭相关融合或声明无对应传感器 |

雷达覆盖范围参考 MID360，但仿真使用规则射线扫描，不能视为精确复现真实 MID360 的非重复扫描时序、回波、材质和噪声。雷达前倾会改变观测覆盖和盲区，不能把盲区未返回的点直接认定为空闲。

仿真图像处理仅识别并标注颜色目标，输出框及像素检测信息；不是已经具备实机缺陷识别能力。

## 3. 坐标系与定位链路

### 3.1 坐标约定

ROS 端采用 ENU/FLU 约定；PX4 内部使用 NED/FRD。MAVROS 执行协议边界所需转换，向 `/mavros/odometry/out` 输入时不能再自行转为 NED。

无 GPS 时采用 ENU 的轴约定不代表已经获得真实地理东、北和地理原点。

| 名称 | 含义 |
|---|---|
| `lidar` | 雷达自身扫描坐标 |
| Faster-LIO `body` / 配置 TF `lio_body` | 算法 IMU 参考坐标，不能直接解释为无人机中心 |
| `camera_init` | Faster-LIO 本次初始化建立的固定世界坐标，与相机无关 |
| `base_link` | 桥接后使用的机体参考中心 |
| LIO 水平世界 | `camera_init` 经当前世界方向修正后的位姿/点云数值 |
| FCU 世界 | PX4 EKF 本次运行维护的本地世界坐标，MAVROS 输出 ROS 约定数据 |
| `odom` | 当前桥接和规划主要使用的标签；两种来源都使用它，存在下述数值对齐细节 |
| `map` | Qt 显示和地图持久化参考系，通过平移和绕 Z 轴旋转与本次控制系对齐 |

### 3.2 Faster-LIO 的原始输出

| 话题 | 内容与参考坐标 | 当前是否使用/发布 |
|---|---|---|
| `/Odometry` | 算法 IMU `body` 在 `camera_init` 中的位姿 | 使用 |
| `/cloud_registered` | 已去畸变、已转换到 `camera_init` 的扫描点云 | 使用 |
| `/cloud_registered_body` | 算法 IMU `body` 系点云 | 当前配置关闭 |
| `/cloud_registered_effect_world` | 世界系中的匹配有效点 | 当前配置关闭 |
| `/path` | `camera_init` 中的历史位姿轨迹 | 发布 |

当前使用的配准点云已经在世界系，不是原始雷达系，也不是只包含匹配约束点的“有效点”话题。Faster-LIO 内部转换为：

```text
p_camera_init = R_world_imu × (R_imu_lidar × p_lidar + t_imu_lidar) + t_world_imu
```

仿真中雷达和其 IMU 共坐标，因此 Faster-LIO 内部 `extrinsic_R=I`、`extrinsic_T=0`。无人机中心到传感器的 30° 安装角和位置偏移在桥接层处理，不应再重复填写成雷达与自身 IMU 的外参。

### 3.3 从算法位姿换算机体位姿

记 `T_A_B` 为把 B 中坐标变换到 A 的变换。桥接使用：

```text
T_LIO水平世界_机体
  = T_水平世界_camera_init × T_camera_init_算法body × T_算法body_机体
```

当前 `T_水平世界_camera_init` 使用固定 `Ry(+30°)`；传感器到机体变换是安装外参的逆。它不是简单减去 XYZ 偏移，而包含随姿态变化的杠杆臂换算。

输出 `/drone/lio/odom`、`/mavros/odometry/out`，标记 `header.frame_id=odom`、`child_frame_id=base_link`。

已配准世界点云只需要世界系变换；不能再给它重复乘机体安装外参。原始雷达点/射线则需要完整机体运动和安装外参。

固定 30° 世界修正基于当前水平机体初始化条件。地图不会仅因雷达前倾而倾斜；任意初始 roll/pitch 的重力对齐仍需专项验证，不能认为已经适配任意倾斜地面启动。

### 3.4 两个 `odom` 是否真的重合？

设计意图是让 LIO 与 FCU 使用一致的导航坐标，但当前没有依据保证其原点和轴方向始终严格相同。

必须区分：

1. 固定的坐标原点/轴方向偏差。
2. 在同一坐标约定下，两套估计器的位置、姿态差异。

定义相同机体参考点只解决“估计哪个物理点”；不会自动统一世界原点和初始航向。即使固定世界对齐已经完成，EKF 经过 IMU 传播、滤波及外部位姿更新，输出也不会每时每刻等于 LIO。

当前桥接按扫描时间匹配 LIO 与 FCU 机体位姿，计算：

```text
T_FCU世界_LIO水平世界(t)
  = T_FCU世界_机体(t) × inverse(T_LIO水平世界_机体(t))
```

用于将配准点云输出为 `/drone/cloud_fcu_world`。位姿匹配容差 0.15 s。仿真原始建图射线与扫描匹配容差 0.015 s，然后使用：

```text
p_FCU世界 = T_FCU世界_机体(t) × T_机体_雷达 × p_雷达
```

射线输出到 `/drone/mapping/rays`，并发布同采集时刻的 `/drone/cloud_body_pose`。

这一步把估计差异也纳入了对齐，因此相对误差变化可能让同一障碍多次落入不同体素。它是地图不稳定的可能来源，不是已经被日志证实的唯一故障原因。

**当前实现不是严格的双世界 TF 分离。**LIO 输出和 FCU 规划数据都使用 `odom` 标签；`/drone/fcu/odom` 是 FCU 数据重标记，不是额外求解一个静态坐标变换。不能通过同名标签推断原始数值完全相等。

可以将 `camera_init` 直接通过固定变换转到统一导航世界，没有数学上必须保留“LIO 水平世界”中间话题的要求。但建立固定世界对齐、让建图使用稳定 LIO 位姿、监测 EKF 残差并处理 EKF 重置，属于后续改造建议，**尚未实施**。

### 3.5 PX4 只融合外部位姿

| 参数/行为 | 当前值 |
|---|---|
| `EKF2_EV_CTRL` | 11：外部水平位置、垂直位置、航向；不融合外部速度 |
| `EKF2_HGT_REF` | 3：外部视觉高度参考 |
| `EKF2_GPS_CTRL` | 0 |
| `EKF2_BARO_CTRL` | 0 |
| `SYS_HAS_BARO` / `SYS_HAS_MAG` | 0 / 0 |
| 仿真 MAVROS 时间同步 | `PASSTHROUGH`，timesync_rate=0；实机应重新验证正常同步 |

当前 Faster-LIO 源码原始 `/Odometry` 实际会填写内部速度，不能写成“当前版本必定没有速度”。但是桥接不把它作为可信速度发送，twist 协方差置大，且 PX4 外部速度融合关闭。

飞控 IMU 参与 EKF 状态传播，位置和速度状态相互关联；“只融合 LIO 位姿”不代表“飞控 IMU 完全不影响位置”。控制端发送的规划速度前馈是控制指令，不是 EKF 外部速度测量。

|---|---|

| `preprocess/blind` | 0.45 m，滤除近距离载具点 |
| `mapping/imu_init_samples` | 400，约 2 s 雷达 IMU 样本 |
| `mapping/min_translation_support` | 30 |
| `mapping/det_range` / `fov_degree` | 40 m / 360° |
| `point_filter_num` | 2 |
| `max_iteration` | 3 |
| `filter_size_surf` / `filter_size_map` | 0.25 / 0.25 m |
| `ivox_grid_resolution` / `ivox_nearby_type` | 0.5 m / 26 |

最低平移约束指标来自独立平面法向对平移的几何支持，不是简单点数，也不是 EKF 位置误差。降低阈值不会自动提高定位精度。

## 4. 地图体系、原点与持久化

### 4.1 两种地图，不是全局/局部两张规划地图

| 地图 | 用途 | 是否直接给 A* |
|---|---|---|
| Faster-LIO 内部点地图/iVox | 点云近邻、局部平面匹配、定位 | 否 |
| EGO `GridMap` 共享三维地图 | 占据/空闲/膨胀，供 A*、EGO 和安全审核 | 是 |

A* 与 EGO 共用第二张地图。当前没有独立二维 costmap，也没有拆成“A* 只读静态地图、EGO 独立维护实时局部地图”。

### 4.2 当前体素几何和边界

| 项目 | 值 |
|---|---|
| 分辨率 | 0.10 m |
| 存储尺寸 | 30 × 30 × 8 m，300 × 300 × 80 个体素 |
| 数组最低角点 | 控制坐标 `[-15, -15, 0.5]` |
| 存储 Z 范围 | 0.5～8.5 m，受索引边界约束 |
| 可导航 XY | 控制系中各 −8～8 m |
| 可导航 Z | 0.5～虚拟天花板减 0.20 m |
| 默认天花板 | 2.5 m，默认最高目标为 2.3 m |
| Qt 天花板修改范围 | 当前 0.8～2.5 m |
| 局部更新范围配置 | 各轴半范围 X/Y 5.5 m、Z 4.5 m |

数组角点不是地图物理原点。控制高度是控制 `odom` 的 Z，不是斜雷达 Z，也不应无条件解释为距离当地地面的净高。

`ego.launch` 中初始虚拟顶层为 2.6 m；飞行管理器启动发布当前天花板后，地图随之更新。使用时以动态天花板为准。

### 4.3 原始占据、空闲与膨胀

仿真建图射线包含命中/未命中区别。命中先立即阻挡，证据每次加 2、最大 3；独立扫描的空闲射线穿过旧体素，每次减 1。同一扫描命中优先，一帧内很多射线不会当作多次独立确认。

一般 2～3 次明确空闲扫描可清除旧障碍。射线在实际回波处停止，不清除障碍后方。没有显式未命中射线的硬件回退只使用真实回波，不凭空生成自由空间。

原始占据变化会更新膨胀引用计数，避免反复叠加膨胀层：

| 参数 | 当前含义 |
|---|---|
| `obstacles_inflation` | 水平 0.40 m，4 个体素 |
| `obstacles_inflation_z` | 配置 0.25 m，向上取整为 3 个体素即 0.30 m |
| 形状 | XYZ 邻域盒形膨胀，不是球体半径 |
| 机体物理自由区域半尺寸 | `[0.235,0.235,0.055] m`，按机体姿态处理 |
| A* 额外保守查询 | 对膨胀障碍加查一层邻居体素，约 0.10 m，不改变显示地图 |

机体外形、膨胀量、到达半径是不同概念。水平膨胀配置注释按约 0.30 m 机体水平半径加余量考虑，真实外形应另行标定。

### 4.4 飞远后障碍会消失吗？

当前 `retain_cloud_obstacles=true`，就绪后点云分支保留历史占据。远离、遮挡、盲区或当前视野未看到障碍，均不是清除证据。

局部窗口限制更新/显示等工作，不等于删除窗口外所有障碍。全局规划读取保留的导航体素状态；不能仅凭 RViz 某个局部点云显示是否出现，判断全局地图有无障碍。

会清除的情况包括：真实空闲射线确认、主动新建/清空地图、重新加载地图替换状态。定位未就绪的初始化阶段可以重置暂存，不能将此阶段等同正常飞行地图保留。

### 4.5 文件格式：当前不是 PCD 启动

默认地图：[inspection_demo_scene.dmap](../start/maps/inspection_demo_scene.dmap)。当前读写 `DRONE_GRID_V1/V2` 格式，含网格元数据及原始占据/空闲证据。V2 还记录地图平移和 yaw 元数据。

加载顺序是“读取体素记录 → 依据初始位姿转换 → 保守栅格化 → 重建膨胀层”，不是“读取 PCD → 从点云建图”。文件不保存反复膨胀后的层，避免加载后二次膨胀。

旋转或非整格平移时，历史空闲体素不一定覆盖完整新体素，因此不导入该空闲证据；障碍则保守转换。仿真启动可只加载当前固定网格覆盖部分，不代表支持无限地图。

运行内存中的地图持续更新；磁盘文件只在显式保存时更新。巡检模式的“预建/静态地图”指启动有先验，不表示当前实现将地图永久锁为只读。

### 4.6 `map` 原点如何确定？

- 在线建图：首次 READY，把起始机体位置设为 `map` 的 `[0,0,0]`，初始机头为 +X。
- 预建地图：保留文件中的参考坐标，通过选定初始位置和 yaw 对齐本次控制系；默认仿真场景地图采用场景参考坐标。
- `map` 与控制系之间只有平移和绕 Z 轴旋转，不再引入地图倾斜。

会话对齐公式：`yaw = desired_yaw - current_FCU_yaw`，`translation = desired_xyz - Rz(yaw) × current_FCU_xyz`。不会为选地图位姿而重置 EKF 或把 LIO 历史轨迹硬改到另一个位置。

### 4.7 预建地图是否帮助 LIO 重定位？

没有。当前只向规划地图加载体素；Faster-LIO 本次重启仍独立初始化并建立内部匹配地图。

初始位姿来自人工选择，仿真按其生成机体。没有旧 PCD 扫描匹配重定位、自动初始位姿识别或回环校正。填写错误不能靠当前预建导航地图自动纠正；长时间 LIO 漂移也没有靠旧地图自动约束。

## 5. 全局导航：三维 A* 与平滑参考路线

### 5.1 是否必须先验地图？

不必须。在线模式基于当前扫描逐步增加环境知识；预建模式启动即具有已加载范围内的障碍知识。

全局路线允许经过未知空间，但必须避开已知膨胀障碍和飞行边界。实际执行必须通过前方已观测空闲检查。黄色线出现，不代表全程已确认可飞。

### 5.2 搜索与平滑参数

| 项目 | 当前实现 |
|---|---|
| 地图输入 | 共享体素增量与恢复快照，非独立累积点云建图 |
| 搜索维度/步长 | 三维 / 0.25 m |
| 邻接 | ±X、±Y、±Z，6 邻接 |
| g / h | 路径长度 / 欧氏距离 |
| 搜索节点上限 | 15000，代码允许配置 1000～60000 |
| 搜索 CPU 批次 | 0.025 s 线程 CPU 时间，跨轮保留 open set |
| 起点连接 | 连续起点安全连接邻近最多 27 个网格中心 |
| 终点连接 | 距离小于 0.5 m 时仍需完整线段安全 |
| 直线捷径 | 完整遍历线段体素，无障碍可直接连接 |
| 平滑 | 三次贝塞尔圆滑连接、切线连续，并检查整条曲线 |
| 最大拐角切入 | `min(0.8 m, 0.42×前段长, 0.42×后段长)` |
| 不安全时 | 切入长度减半，最小约 0.015 m；失败重新寻路 |
| 采样 | 曲线约 0.035 m、直线约 0.04 m；相邻方向变化约 ≤4° |
| 路线大小 | 最多 2048 点 |

这不是仅为显示画圆弧。平滑后的点序列通过 `/drone/global_route` 进入 EGO；`/drone/global_path` 和 markers 显示同一参考几何。黄色实线表示已观测空闲，虚线表示待观测。

### 5.3 全局重规划与进度

存在当前目标时后台约每 0.1 s 检查；无目标直接跳过搜索。进度使用沿路线弧长，限制单次前进幅度，避免相邻曲线或交叉路径投影导致进度跳跃；允许投影距离约 0.75 m。

完整剩余路线仍安全时继续沿用，不每次检查都全量 A*。安全路线约 0.5 s 刷新发布，不等于搜索频率。

新目标、新障碍切断路线、无法安全连接剩余路线、天花板改变或未找到完整路线，可启动新搜索。搜索结束后的重试间隔约 1 s 墙钟；搜索起点已与机体相差超过 0.5 m 时重建搜索。

路线被切断时保留安全前段，后台计算完整替代路线。部分路线可以显示，但 EGO 安装要求末端到达当前目标；不能靠安全前段无限前进。地图/位姿/时钟失效会清除不可靠参考路线。

## 6. 全局路线如何进入 EGO 局部规划

### 6.1 滚动规划，而非提前切固定段

当前 `fsm/use_global_route=true`，走修改后的 `getRouteTarget()`：

1. 检查完整路线的任务身份、坐标、时间和终点。
2. 把规划起点投影到参考曲线。
3. 从投影沿曲线截取前方最多 5 m **弧长**。
4. 保留沿途密集曲线点，不换成起点到局部终点的直线弦。
5. 用参考点初始化三次均匀 B 样条，并加入参考路线贴合优化项。
6. 优化平滑、避障和运动可行性，审核后执行；随运动继续滚动规划。

完整路线安装要求：`odom`、2～2048 点、年龄 −0.02～2 s、终点距当前目标 ≤0.02 m。起点离路线超过 0.75 m 时拒绝直接使用。

不到最终目标的局部末端速度沿参考路线末段有向切线；到达最终目标的末端速度为 0。普通局部最短距离约 0.1 m，终点接近阶段可放宽到 0.02 m。

### 6.2 EGO 参数

配置源：[ego.launch](../src/drone_stack/launch/ego.launch)、[advanced_param.xml](../src/ego_planner/src/planner/plan_manage/launch/advanced_param.xml)。

| 参数 | 当前配置 |
|---|---|
| `planning_horizon` | 5 m 弧长 |
| 任务速度 | 默认 0.5 m/s，Qt 设置范围 0.1～1.0 m/s |
| `max_acc` / 配置 `max_jerk` | 0.5 m/s² / 4 m/s³；配置值不等于已验证实机硬保证 |
| `control_points_distance` | 0.4 m |
| 参考种子采样 | 约 0.2 m，8～128 个样本，实际间距受样本上下限影响 |
| `feasibility_tolerance` | 0.05 |
| `thresh_replan` | 离当前局部轨迹起点超过 1.5 m 的常规重规划条件 |
| `thresh_no_replan` | 终点附近 2 m 抑制普通重规划；终点逻辑另处理 |
| FSM / 碰撞定时器 | 0.01 / 0.05 s；不代表每 0.01 s 都运行一次优化 |
| 失败退避 | 0.2 s 仿真时间 |
| 平滑/避障/可行性/参考贴合权重 | 1.0 / 0.5 / 0.1 / 1.0 |
| `optimization/dist0` | 0.5 m，优化软避障距离，不是再加一层硬膨胀 |
| `traj_server/time_forward` | 0.1 s |

EGO 内部还可以用局部 A* 为碰撞反弹优化寻找引导，不是另一套抢占任务的全局路线。原有 waypoint 入口仍在 launch 中，但当前任务通过管理器与 `/planning/start` 握手启用；本节描述的是实际开启的统一全局路线分支。

黄色是参考路线，紫色是批准后的局部运动轨迹；EGO 为平滑和避障可偏离参考路线。紫色不是独立显示节点伪造的轨迹，显示层在黄色上方，机体红色朝向箭头在最上层。

## 7. 执行、安全审核与任务队列

### 7.1 控制输出

EGO B 样条经审核后，通过轨迹服务器形成位置命令。飞行管理器向 `/mavros/setpoint_raw/local` 持续发布约 30 Hz 位置、规划速度前馈及 yaw。

HOLD、转向、解锁准备等阶段也持续发布对应设定值，避免因为操作员没有持续点击而退出 OFFBOARD。没有新的人工指令不等于必须降落；健康故障、通信/控制断流及飞控保护是另外的触发条件。

### 7.2 曲线安全审核

- 检查轨迹身份、数值、时间和速度等合法性。
- 对三次曲线使用控制凸包及递归细分进行连续体素碰撞、飞行边界审核，不只是抽几个显示点。
- 检查前方至少 3 s 已观测空闲空间；动态前视时长还包含速度、减速和数据年龄余量。
- 当前命令与机体之间的连接也需满足安全/空闲要求。
- 未知或不安全不能当作可执行自由空间；等待、悬停或重新规划。

`validate_curve` 默认墙钟预算 2 s、线程 CPU 预算 0.05 s、节点预算 10000；这三个限制不同，延长墙钟等待不能无限放开 CPU 消耗。

### 7.3 多目标队列

Qt 支持连续点选，队列最多 100 点。只有当前目标发布为 `/drone/navigation_goal`；到达或跳过当前点后再计算下一点，避免预先为全队列搜索。

在线模式已知障碍内的目标会跳过该点并继续后续目标；数据健康故障等导航取消不能等同这种单点跳过。地图切换需落地、未解锁、READY、健康且空目标队列。

### 7.4 终点接近与收敛

| 项目 | 当前值/机制 |
|---|---|
| 接近阶段启动距离 | 沿路线 `max(0.8 m, v²/(2×0.4)+0.3 m)` |
| 终点低速配置 | 0.2 m/s；不能把起始边界速度突然截断 |
| 减速度配置 | 0.4 m/s² |
| 最终轨迹 | 末端零速度，使用平稳停止的时间参数化 |
| 到达位置 | 三维欧氏距离 ≤0.15 m，**球形**，非 XYZ 各 ±0.15 m |
| 到达速度 | 测量速度 ≤0.15 m/s |
| 到达持续 | 1 s |
| 确认退出滞回 | 0.20 m，持续越界约 0.5 s 才处理；不是刚越 15 cm 就重规划 |
| 收敛配置时长 | 3 s，确认阶段超时上限还包含约 1 s 余量 |

等待、转向期间也检查到达，避免实际已经到点却再次规划或转向。到达后当前目标及其路径显示清除，队列有后续点则继续调度。

## 8. 机头如何沿路线调整？

朝向来源是**批准执行的紫色 B 样条**。在对应位置命令时刻求导：

```text
yaw_desired = atan2(dy/dt, dx/dt)
```

这是水平投影的有向切线，不是朝最终目标的直线、测量速度方向或位置跟踪误差方向。起步导数为零时沿同一轨迹向前约 0.10 m 找方向；纯垂直移动或停止时保留 yaw。

| 规则 | 当前值 |
|---|---|
| 正常移动 | 边前进边调整 yaw |
| yaw 设定值变化上限 | 30°/s |
| 前向视野约束 | 切线相对设定 yaw 和实际 yaw 都检查 ±60° |
| 起步/超出视野 | 暂停移动，悬停转向，清理旧局部轨迹并重新规划 |
| 制动条件 | 速度 ≤0.1 m/s，稳定约 0.2 s |
| 转向完成 | 实际误差 ≤10°、低速、定位健康、命令转到目标 |
| 后续等待 | 稳定 0.3 s，并收到稳定后的新扫描/地图 |
| 转向超时 | 20 s |

因此机头不保证每时每刻严格与切线重合：yaw 有速率限制、飞控有响应延迟，急弯时会有偏差。当前没有按曲率进一步联动限速来保证严格切向。roll/pitch 由 PX4 为运动控制，不要求机体完整三维姿态沿轨迹切线。

## 9. 健康状态与保护时序

当前统一发布 `/drone/flight_health` 等状态，Qt 显示健康绿色、警告/HOLD 黄色、严重红色。电量 >60% 绿色、20%～60% 黄色、<20% 红色。

| 条件/数据年龄 | 当前值 |
|---|---|
| 短暂普通健康下降 | 警告，保留严重异常立即保护 |
| 持续普通异常 | 1 s 取消导航并 HOLD |
| 持续普通异常进一步恶化 | 2 s 降落 |
| 严重数值错误/跳变等 | 可以立即降落，不必等待上述时长 |
| LIO 几何恢复稳定 | 0.5 s |
| EGO 心跳数据 | `/planning/data_display`，不是 `/planning/heartbeat` |
| EGO 心跳年龄上限 | 1 s |
| FCU odom 年龄上限 | stack.launch 配置 0.70 s |
| 位置命令年龄上限 | stack.launch 配置 0.50 s |
| estimator_status 年龄上限 | 2 s；未改成 1 s |
| LIO 健康快照年龄 | 0.5 s |
| 地图年龄 | 2 s |
| 启动等待 | 管理器至少等待仿真时间 65 s 等启动条件 |

健康门还检查 LIO 有效性、EKF 水平/垂直位置与速度有效标志、时间与位姿新鲜度等。当前管理器不是直接按 EKF 创新比率设置另一组阈值；创新异常可能先影响飞控自身估计有效性，分析原因需查原始 EKF 数据。EGO 心跳过期会取消导航；与 EKF/LIO 异常的 HOLD/降落时序不能混为同一门槛。仿真时间门槛不是墙钟秒数，实时因子下降会延长人工感受到的等待。

请求降落优先使用 PX4 `AUTO.LAND`；拒绝时且仍有新鲜位置才使用管理器下降回退。位置不可用时不能保证软件回退安全降落，需要 PX4 失效保护/人工接管。详细行为以当前管理器与 PX4 参数为准。

## 10. 两种模式、Qt 与分离启动

### 10.1 建图模式

不加载旧地图，本次实时建图。在线原点自动设置。允许实时导航，落地后可保存 `.dmap`。

### 10.2 巡检模式

预览预建地图，人工选初始位置并拖动方向，确认后按该位姿生成仿真机体。定位与地面状态就绪后加载地图，开放导航。当前已接入人工选区后的单区域下视覆盖任务，详情见 [巡检功能](INSPECTION.md)；尚未完成该新增功能飞行验收，也没有自动缺陷识别或自动旧地图重定位。

### 10.3 两个终端

终端 A：

```bash
cd /home/d/robotproject/project0
bash start/start_gazebo.sh
```

先启动 ROS master，等待出生请求，再启动 PX4/Gazebo。默认打开 Gazebo 窗口；`DRONE_SHOW_GAZEBO=0` 隐藏窗口。`DRONE_SIM_WORLD` 可指定其他世界，但巡检地图必须与场景对应。

终端 B 二选一：

```bash
cd /home/d/robotproject/project0
bash start/start_navigation.sh mapping
# 或
bash start/start_navigation.sh inspection
# 或指定地图
bash start/start_navigation.sh inspection /绝对路径/场景.dmap
```

终端 B 同时启动 MAVROS、Faster-LIO、EGO、地图会话、飞行管理器、相机处理和 Qt。巡检必须等待用户选初始位姿，不能先固定生成机体再任意改地图初始位置。

两脚本分别拥有自己的进程组，禁止重复启动或与旧 [start_simulation.sh](../src/drone_stack/scripts/start_simulation.sh) 混用。切换模式/出生位姿需落地未解锁，先停止 B 再停止 A，再开启新会话。

统一停止入口为 `bash start/stop_all.sh`，按项目身份与子进程关系清理两种启动器及后台节点，依次使用 SIGINT/SIGTERM/SIGKILL，不删除地图或实验数据。该命令不是降落操作。分离入口与旧一体入口均默认随仿真启动 Gazebo 界面；旧入口的 `--no-gui` 仍可用于后台启动。

### 10.4 启动数据检查

[check_sim_startup.py](../src/drone_stack/scripts/check_sim_startup.py) 被动检查：

- 时钟推进、雷达点/IMU、去畸变配准点云。
- LIO 位姿、外部位姿输出和 FCU 里程计。
- MAVROS 连接、建图射线、体素增量。
- 两路处理图像、管理器心跳。
- 地图会话模式、对齐、READY/HEALTHY。
- EGO `/planning/start` 服务和 EGO/Qt 节点注册。

检查内容包括连续接收、时间推进/新鲜度、位姿数值/四元数、点云字段和尺寸等基础合法性。连续正常 3 s 才记录通过。

出生请求前等待人工操作不计超时；提交后默认 600 s 墙钟超时。没有任务时 EGO 未启用执行 FSM，不要求运动轨迹/执行心跳，也不会为了检查而自动开始飞行。

日志分别在 `start/logs/world_*` 和 `mapping_*`/`inspection_*`；导航目录下 `startup_check.log/json` 写入原因和结果。检查失败只报告，不自动杀死定位/控制节点；通过是启动快照，不代替飞行中实时保护，也不证明 GPU 实际显示效果或完整导航通过。

### 10.5 Qt 功能

- 综合三维地图与二维俯视选点、滚轮缩放。
- 黄色全局参考、紫色局部执行、绿色实际轨迹、红色目标与机头方向。
- 连续目标队列、目标高度、任务速度、虚拟天花板。
- 操作授权、ARM、相对起飞高度、HOLD、取消、降落、落地 DISARM 等操作。
- 地图新建、保存、选择文件、预览、初始位置和朝向、加载导航。
- 顶部连接/定位/规划等状态颜色及两路处理图像。

授权与 ARM 是不同步骤；启动脚本不会自动授权、解锁、起飞或导航。

### 新增巡检接口说明

巡检与普通点到点共用统一全局参考输出和 EGO 执行链路。巡检管理器提交前方12m参考，EGO滚动取5m；中间窗口继续，最终窗口停止。GlobalRoute增加巡检身份、连续运动、revision和受阻标志，StartPlanning增加巡检/连续标志。受阻黄色前段可以显示，但不得安装为可执行完整参考。配置、状态、记录和限制详见 [INSPECTION.md](INSPECTION.md)。

### 三页操作台、已知区域和AI

Qt分为综合、区域巡检、AI文本控制。综合与巡检复用一个地图渲染器，AI页使用完整文字空间；顶部状态与一键降落公共。巡检页高度独立设置，区域库按实际加载 `.dmap` 文件的SHA256隔离，存多边形和参数，加载后重新生成路线。

AI通过完整 `submit_plan` 解析、白名单校验后，逐步调用现有控制接口并等待实际结果。云端解析与执行授权分开，飞行授权保持原入口。Qt会话、AI请求代次、导航任务ID及巡检来源共同阻止迟到结果/取消跨任务生效。AI起飞/导航由飞行管理器独立监视来源，AI巡检由巡检管理器独立监视；人工继续可接管暂停任务。降落不会被AI停止改为HOLD。

详情、凭据位置和接口见 [AI_CONTROL.md](AI_CONTROL.md)。新增功能尚未完成真实ROS/Gazebo与云端API联调，离线检查与编译不能视为飞行验收。
